# 广义 N×K Gomoku 游戏与自适应搜索实验报告

## 1. 总体设计

### 1.1 游戏目标与规则

游戏程序需要正确实现双方轮流落子、合法性检查、四方向 K 连判胜及和棋，并在指定时限内返回合法落点。课程基础搜索要求为 Minimax + Alpha-Beta，配合深度截断、评估函数和合理候选生成。迭代加深、着法排序和 MCTS + UCT 作为扩展实现与比较对象。

棋盘为 N×N 二维数组：0为空、1为黑、2为白。黑棋先行，每步在空位放置一子。横、竖或两种对角线连续同色棋子达到或超过 K 即获胜；满盘无人获胜则和棋。本项目采用无禁手规则。

N、K为整数，要求 `3 <= K <= N`，只由构造参数决定。课程范围 `5 <= N <= 15`、`3 <= K <= N` 的组合数为 `sum(N-2, N=5..15)=88`。核心未固定 N 上限，但没有保证任意极大棋盘在相同时限内具备相同棋力。棋盘窗口、邻域和权重均在运行时生成。

### 1.3 三种对战模式与 N/K 配置

人人模式由两名玩家轮流输入坐标，调用同一 `GomokuGame.play` 检查合法性和终局；人机模式按玩家棋色创建另一方的协议 AI，每轮传入棋盘、对手上一落点和时限；机机模式加载两份本地协议 AI，交替调用至终局或判负。三种模式均将 `--board`、`--win` 传给游戏及 AI 构造函数，默认 N=15、K=5。AI 调用通过独立进程隔离，游戏层负责最终合法性和结果判定。

`python main.py` 启动人机模式，`--mode hvh/hva/ava` 分别选择人人、人机和机机，`--board N --win K --time 5` 配置规则与预算。完整运行方法见 [README.md](README.md)。游戏无需外部网站、CDN或在线引擎。

### 1.4 统一协议、参赛入口与落子安全

`assignment1/gomoku_ai.py`当前对应 Adaptive Search。文件完整包含 Depth Search 和 Monte Carlo 的独立实现及选择器，可单独加载，不依赖兄弟文件。Depth Search 和 Monte Carlo 的独立版本保留为游戏模型。协议文件名、类名和签名不变，界面 Adaptive Search 也调用此入口。

参赛入口保留课程基础 Minimax + Alpha-Beta 搜索及独立 MCTS + UCT，Selector 每步调用其中一个主搜索器，并非所有局面都执行 Alpha-Beta。单文件打包只为协议部署，不改变两套树的独立性或选择规则。

三种模型均保留课程接口：

```python
class GomokuAI:
    def __init__(self, player_id, board_size, win_length):
        ...
    def get_move(self, board, last_opponent_move, time_limit):
        ...  # 返回整数二元组 (row, col)
```

每局重新创建实例，输入棋盘只读，内部使用独立状态；坐标从0开始。`last_opponent_move` 可为 `None`，搜索不依赖它一定存在。每步先选合法后备落点，搜索中断保留已完成结果。Adaptive Search 的异常路径也能使用后备落点，裁判独立检查超时、非法和异常。

判胜围绕最后落子向四个方向的两侧延伸，无需每步扫描所有棋盘线。棋谱保存玩家与坐标，实验结束独立重放，核查轮次、占用、越界、终局后落子和最终结果。

## 2. AI 算法说明

### 2.1 Depth Search：Minimax、评估与剪枝

#### 2.1.1 Negamax 与深度截断

Depth Search 用 Negamax 表达零和 Minimax：当前玩家价值为对手价值的相反数，递归窗口变为 `[-beta, -alpha]`，当价值达到 beta 时剪去其余分支。终局使用远高于静态分数的胜负值，并倾向更早获胜、延迟失败。

搜索受深度、时间和候选宽度限制，是选择性搜索，不是全盘完全求解。Alpha-Beta不改变同一候选树上的Minimax结果，但候选筛选本身可能排除非明显战术的远处着法。

以下伪代码概括主框架；实际实现另外处理强制应手扩展、置换表界限与状态撤销：

```text
GET_MOVE(board, time_limit):
    fallback ← 一个合法空位
    deadline ← 开始时间 + time_limit - reserve
    若存在直接胜点或唯一直接防守点：返回该点
    best ← fallback
    对 depth = 1 .. min(max_depth, empty_count)：
        尝试用 NEGAMAX 搜索本层，按此前最佳结果排序
        若本层完整完成：best ← 本层最佳落点
        若截止时间到：中断，保留 best
    返回 best

NEGAMAX(state, depth, alpha, beta, player):
    检查截止时间
    若终局：返回当前玩家视角终局值
    若达到截断且无待处理强制威胁：返回评估值
    moves ← 生成并排序候选
    value ← -∞
    对 move in moves：
        落子
        尝试 score ← -NEGAMAX(child, depth-1, -beta, -alpha, opponent)
        无论正常或中断均撤销落子
        value ← max(value, score)
        alpha ← max(alpha, score)
        若 alpha >= beta：停止其余候选
    返回 value
```

#### 2.1.2 K 自适应评估

程序生成四方向所有长度 K 的窗口。同时含双方棋子的窗口无法成为任一方的连 K，贡献为0；仅含一方棋子时按数量递增评分。非终局整数权重比例为：

```math
w(j)=8^{j-1},\qquad 1\le j\lt K.
```

整数增量配合缩放表示评估，避免浮点撤销累计漂移。终局另用胜负常量。开放端、封闭端及空隙棋型主要通过重叠 K 窗口的可用性间接反映，并非完整的活三、冲四显式分类器。

K−1子且仅剩一个空位的窗口给出一步胜点。双威胁检查一次落子后是否产生多个不同的胜点，并对重叠窗口的同一胜点去重。以上计算来自当前棋盘，不是预计算固定应答。

#### 2.1.3 候选与战术

普通候选为已有棋子半径2邻域中的空位；空盘中心为一般性开局启发。直接获胜、对手胜点和强制威胁优先处理，不受普通宽度截断影响。排序结合进攻、防守、强制威胁和中心偏好。默认根宽24、分支宽12，必要战术候选可能使实际数量超过该值。

#### 2.1.4 迭代加深、排序与置换表

搜索从深度1逐层加深，每完整完成一层才更新主结果；超时返回最后完整层结果。名义最大深度为10，当前迭代上限为 `min(10, empty_count)`。这不代表每步实际完成10层。强制应手扩展可越过普通截断，额外威胁分支受默认 quiescence 参数6控制。

排序优先上一完整层最佳着法和置换表着法，再使用killer/history与静态评分。置换表保存精确值或上下界，默认容量100000。每步重建表与排序历史，因此上一回合完成深度不等于复用搜索树。

落子与撤销只更新受影响窗口，并在超时异常路径恢复状态。算法不识别对手身份，也不使用针对 Depth Search/Monte Carlo 的特殊应答规则。

### 2.2 Monte Carlo：独立 MCTS + UCT

#### 2.2.1 四阶段及最终选择

Monte Carlo 每次模拟执行Selection、Expansion、Rollout、Backpropagation。UCT选择路径，候选着法扩展节点，启发式策略模拟后续对弈，终局价值沿路径回传。最终选择根节点访问最多的子节点，次数相同再比较平均价值；两者均相同时保留子节点列表中最先出现的节点。

#### 2.2.2 统一价值视角

节点保存根玩家奖励：胜+1、和0、负−1。选择时根据行动方调整平均价值符号：

```math
UCT_i=s\frac{Q_i}{n_i}+C\sqrt{\frac{\ln n_p}{n_i}}.
```

根玩家行动时 `s=1`，对手行动时 `s=-1`；未访问节点优先探索。默认 `C=sqrt(2)`，可配置。对手层不能同样最大化根玩家收益，否则会产生视角错误。

#### 2.2.3 候选筛选与启发式模拟

Monte Carlo 以邻域候选、运行时窗口攻防评分和战术保留降低分支。默认宽度随K计算：

```text
root_width   = min(18, max(10, 2*K + 2))
branch_width = min(12, max(6, K + 3))
rollout_width = 6
```

Rollout优先直接胜、阻挡直接败、制造和处理威胁，再从高评分候选随机选，并保留默认0.15随机性。默认长度上限N²覆盖整盘剩余路径；不调用Alpha-Beta。

搜索使用独立 `random.Random`，复制扁平棋盘和窗口计数，不对整个搜索器deepcopy。增量更新与局部判胜减少重复扫描。正式模式按时间停止，固定模拟数仅用于诊断复现。

```text
MCTS(board, deadline):
    先处理根节点直接战术与精确必和
    root ← 当前局面
    当时间未到：
        state ← 本次模拟的独立状态副本
        node ← root
        按行动方视角 UCT 选择，直到未完全扩展或终局
        若可扩展：从筛选候选扩展一个子节点
        reward ← 启发式 Rollout 的根玩家胜负值
        将同一根玩家 reward 回传，更新 visits 与 value_sum
    返回 root 中 visits 最多的合法子节点；无子节点时使用 fallback
```

### 2.3 共用优化与时间管理

两套搜索均使用合法后备落点、运行时战术检查、增量状态更新和时间中断恢复。明显的己方一步胜优先落子；对手存在唯一直接胜点时优先阻挡。存在多个胜点时，阻挡其中一个不保证挽救必败局面。

**精确必和识别**：若所有长度K窗口都已含双方棋子，未来新增棋子也无法恢复任何窗口的连K可能性，因此可准确判为必和。Depth Search在根局面检查，Monte Carlo在根、树节点和Rollout中增量检查并回传0；正式游戏仍返回合法落子，由裁判结束对局。

**有效深度限制**：迭代加深上限为 `min(max_depth, empty_count)`，避免空位不足时反复搜索相同路径；强制应手扩展保留。以上两项的受控效果见3.7。

**统一时间预算**：三种模型均采用：

```math
r=\min(0.08,0.2\,time\_limit),\qquad deadline=t_0+time\_limit-r.
```

每步5秒时，可用总预算为4.92秒。Adaptive Search的预处理、选择器和内部搜索共享同一个绝对截止时间，内部搜索只获得剩余预算。较短时限按比例预留；时间预留提供返回余量，但不是任意机器负载下的硬实时保证。

### 2.4 Adaptive Search：根据局面选择搜索器

Depth Search与Monte Carlo提供两种不同的有限预算搜索方式：前者依靠评估、排序与剪枝逐层加深，后者依靠模拟逐步估计候选价值。Adaptive Search的目标是根据局面复杂度选择更合适的完整搜索器，而非固定使用一种算法。

选择器使用邻域候选数、棋盘进度，以及最近Alpha-Beta搜索的完成深度、中断情况和预算可比性。候选较少时倾向Depth Search；若最近且可比的搜索因时间中断而深度不足，则倾向Monte Carlo。其他局面通常使用Monte Carlo；残局允许依据可靠、可比的历史深度重新选择Depth Search。

```text
ADAPTIVE_GET_MOVE(board, last_opponent_move, time_limit):
    fallback ← 合法空位
    deadline ← 本步开始时间 + time_limit - reserve
    先处理己方直接胜点、对手唯一直接胜点
    candidates ← 当前邻域候选
    algorithm ← Selector(候选数、棋盘进度、可比搜索历史)
    若 deadline 已到：返回 fallback
    用剩余预算仅调用所选完整搜索器
    检查结果合法性；异常或无结果时返回 fallback
```

两套搜索树保持独立，不在MCTS的Rollout中调用Alpha-Beta，也不在Alpha-Beta中调用MCTS。外层预处理不修改输入棋盘、不消耗MCTS随机数，也不先运行两套搜索后比较结果。固定模拟数的一致性检查见3.7.1。

候选数只是复杂度的近似：它不反映评分差距或剪枝后的实际宽度。当前选择器参数属于工程设定，未证明最优；具体值集中列于附录A。残局回切的棋力价值也尚未获得实证支持。

### 2.5 对不同 N、K 的自适应机制

棋盘长度和获胜连子数来自构造参数。长度K窗口、窗口所属格、邻域、权重和战术胜点在构造或落子时计算；棋盘进度用已占格数除以N²归一化，搜索深度受剩余空位限制，MCTS宽度随K生成。Selector不包含特定N/K的算法选择分支。这里的自适应指无需为每个配置改代码，并不表示所有合法配置有相同胜率。

## 3. 实验评估

### 3.7 哪些优化得到诊断支持

本节只保留三项直接影响实现可信度或搜索成本的诊断；它们是局面测试，不与正式对局合并计算胜率。

#### 3.7.1 Adaptive Search 的MCTS分支与纯Monte Carlo一致

修正前后各80局面×3 seeds，共各240对固定模拟比较，全部通过。进入搜索的样本比较候选顺序、扩展轨迹、节点访问与价值、最终着法及RNG状态；另86次对象复用和16次插桩等价检查通过。

这支持覆盖样本中的搜索逻辑一致。正式按时间对弈时，选择器改选Depth Search、预处理占时、完成模拟数和此前RNG消耗仍可能造成不同结果，不能要求两个模型每回合落子相同。

#### 3.7.2 Move Ordering 有效

在相同候选集上，以24局面比较当前、静态与坐标排序，共72次调用：

| 排序 | 平均完成深度 | 首着法cutoff比例 | 根最佳在前3候选比例 |
| --- | --- | --- | --- |
| 当前 | 5.71 | 96.85% | 88.32% |
| 静态 | 5.62 | 约93.4% | 约85.9% |
| 坐标 | 5.29 | 约92.0% | 约63.8% |

当前排序比坐标排序更容易优先搜索有效候选，并完成更深迭代；相对静态排序增益较小，因此保留当前策略。cutoff比例以发生cutoff的节点为分母，根最佳着法指选择性树内结果；这些比例不是全宽树的最优覆盖率。

#### 3.7.3 精确必和与深度限制减少无效搜索

| 受控测试 | 修改前 | 修改后 |
| --- | --- | --- |
| 19个必和局面×3 seeds，Depth Search平均秒 | 1.686004 | 0.000850 |
| 同批局面，Monte Carlo平均秒 | 4.920091 | 0.001826 |
| 剩4空位的Depth Search局面 | 深度10、209节点 | 深度4、59节点 |

必和早停避免在已经无法获胜的局面继续消耗预算；深度限制删除没有新增路径的迭代，示例着法 `(0,3)` 与值0保持一致。它们直接支持“减少无效计算”，不等于证明所有阶段的吞吐或比赛胜率均提高。

其余评估、UCT、候选特征及残局回切诊断没有足够证据支持新调参，概要见附录B。

### 3.8 主批次完成情况与异常处理

统一预算循环对战共280局：15/5三配对各40局，Depth Search–Monte Carlo在5/3与9/4各40局，另外两配对在小棋盘各20局。主批次全部重放通过，无超时、非法或异常。

此前另有一次进程级墙钟超时，具体成因未确认；原失败记录保留在开发目录，正文表格使用相同seed重跑后的正常记录，未将失败尝试计入。因此主批次“0异常”不代表所有运行尝试均无异常。随机基线、自我对战与深度对照另计，不与280局循环对战合并。

## 4. 讨论与反思

### 4.1 Alpha-Beta与MCTS谁更好？

目前没有稳定的全局赢家。当前统一预算下，5/3与9/4胜负相等，15/5下Depth Search仅以21:19略占先；相近胜负不能证明两者在所有局面等强。它们的计算成本也不同：Alpha-Beta受候选宽度、状态更新成本和实际深度限制，MCTS受模拟吞吐与Rollout策略偏差影响。不能只比较名义深度、模拟数或平均用时。

### 4.2 Adaptive Search是否成功？

作为通用实现，它在同一协议下选择一个独立搜索器，保持N/K自适应并完成随机基线与循环对战验证。作为棋力方案，它在15/5当前样本中对两者略占优，小棋盘没有观察到胜负差异；这还不能证明它普遍优于两套纯搜索器。

尤其是“低复杂度残局应回切Alpha-Beta”仍属工程假设：残局诊断未显示已求解着法质量优势，且部分局面本来已经必和。因此不能为了保留Adaptive Search而强化没有收益证据的回切规则。

### 4.3 哪些优化真正有效？

证据最明确的是Move Ordering、精确必和识别和剩余空位深度限制：前者在同一候选集上优于坐标排序，后两者减少了可明确识别的无效计算。固定模拟一致性检查则提高了实现可信度。3.6另表明，增加名义搜索深度在15/5的受控开局样本中有明显收益。

这些结论分别涉及排序效率、运行成本、正确性与样本内对弈表现，不能合并为“Adaptive Search全面提升棋力”。现有诊断也不足以替换评估权重、UCT常数或选择器阈值。

### 4.4 局限与下一步改进

实现的主要困难是有限时间下兼顾分支规模、增量更新和战术正确性。当前评估用重叠K窗口间接表示开放端和空隙，未完整显式分类所有棋型；候选剪枝可能遗漏远处着法，启发式Rollout也可能产生偏差。

实验仅使用有限开局，换色对局、重复seed与部分源残局存在相关性；自我对战每配置只有4局，15/5强对手每配对40局，尚未达到50—100局的进一步验证目标。既有超时和机器负载影响也不支持任意配置的硬实时保证。

后续应优先增加独立开局、随机种子和有效安静残局，检查近高评分候选数与实际完成深度的关系。只有发现稳定收益后才修改评估、模拟策略或Selector；若回切持续没有着法质量收益，应简化规则。当前可以可靠报告的是样本内结果与明确成本节省，而不是普遍棋力优势。

## 附录B：其余诊断的证据边界

**评估函数**：K=3到15的130项人工断言通过，未发现支持修改权重的正确性问题；这不证明权重最优或任意多威胁识别完备。

**残局回切**：72个合法非终局局面覆盖多个N/K，每个3 seeds、两算法同5秒，共432调用。双方着法65个可完整比较，质量相同65个，另7个未知；19个局面已永久必和。重复稳定性不等于更强棋力，当前集合未证明Alpha-Beta在残局更值得选择。

**MCTS效率与UCT**：固定1000模拟的小集合耗时改善，但固定时间阶段测试并非全面改善，中局模拟吞吐由约2938降至2475次/秒。C=0.7、1、sqrt(2)、2的代理评估依赖Monte Carlo自身且样本小，不能认定C=1最优，因此保留默认常数、宽度和策略。

**候选与历史特征**：邻域候选数不包含评分分布，两算法也有不同的实际宽度；877条历史日志仅9条具有此前真实Alpha-Beta搜索信息，无法确定历史深度、新鲜度或阶段对质量及胜负的独立预测力。进一步设计有效分支指标前应先收集证据。
